# 任务三40秒速度调整

现场反馈：`TIMEOUT DA T40.0s`、`P8 F4 S993`。F4是整圈40秒超时；按当前DA弧段1256mm，还距名义里程约263mm。这一读数证明车辆进入DA后触发时间门槛，不是本趟丢线故障；没有各阶段日志，仍无法精确拆分实车转向、捕获与巡航耗时。

## 参数调整

| 任务三参数 | T16 | 本版 |
| --- | --- | --- |
| 斜线巡航 | 200mm/s | 240mm/s |
| 半圆巡航 | 200mm/s | 200mm/s |
| 单轮转向 | 60mm/s | 80mm/s |
| 起步 | 50mm/s | 50mm/s |
| 加速 | 100mm/s²，引用任务一参数 | 150mm/s²，任务三独立参数 |
| 末端减速窗口 | 150mm | 100mm |
| 末端速度下限 | 40mm/s | 60mm/s |
| 入弧捕获 | 50mm/s | 50mm/s |
| 整圈超时 | 40秒 | 40秒 |

调整目的是为转向、找线与最终停稳留时间余量。保留T16的有效黑线纠偏捕获，原PI、半圆巡线增益和差速上限、任务一/二及独立半圆参数不变。捕获60mm/2秒、转向80mm/4秒、丢线100ms、±3°对正及200ms停稳条件保持。没有以放宽40秒门槛来宣称完成任务。

配置集中在 `Core/Inc/car_config.h` 的 `DPT_TASK3_*`；新增独立加速、减速窗口与最低行驶速度参数。核心配置验证允许行驶末端下限60mm/s高于起步50mm/s，因为加速斜坡仍在速度计算最后限制起步目标；两者用途不同。默认独立核心配置仍保守，实际Sunward明确覆盖任务三参数。

## 时间预算与验证

根据题目第二页要求（3），AC→CB→BD→DA一圈用时不大于40秒。PDF是用户提供的任务背景，本次没有执行其中其他参赛规定或改变用户现有STM32工程范围。

在实际CarApp调度下用编码器理想跟随目标速度、假设140mm轮距、理想弧线传感器/航向反馈的相同模型比较：T16参数39730ms，本版33160ms，减少约6570ms。该模型没有电机饱和、轮胎打滑、探头安装偏置、实际轮距/弧线覆盖等动力学，模型结果不能作为真实场地时间或路线验收。

新增精确超时回归：DA阶段S993、达到40秒时仍双轮输出零并锁存F4/TIMEOUT，没有误发完成提示。实际CarApp/兼容入口任务一/二/三ASan/UBSan回归均通过，包含T16左右偏线捕获、完整五次声光、无后退命令、启停与所有既有保护。新斜线最大目标含航向纠偏约255mm/s，半圆最大目标仍约280mm/s，都低于既有350mm/s测速保护门槛；这不能证明实物一定能跟踪目标。

全量ARM编译49单元通过，FLASH42844B、RAM5528B，仅原main未使用诊断警告。实际ELF/HEX闪存内容逐地址一致，实际工程HEX与验证过的暂存镜像相同，且不同于T16。哈希、备份和修改清单见 `安装记录.json`。
