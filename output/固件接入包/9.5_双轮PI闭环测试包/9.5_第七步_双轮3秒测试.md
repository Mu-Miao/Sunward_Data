## 下载后这样操作

1. **固定车身，双轮架空**，使能OFF，打开电池主电源。
2. 下载`/Users/mzh/STM32Cube/Sunward/build/Debug/Sunward.hex`。串口115200/8N1连接后Reset，确认提示`DPI: send RUN! or STOP!; both forward; 3s; UART async`。
3. 待机UL/UR/IL/IR均应为0；BAT应接近此前电池接通时约1340～1350的读数。
4. 使能ON，等1秒，ASCII单次发送`RUN!`，不要循环发送。观察两轮都向前、无明显反复启停，约3秒同时自动停。
5. 若第一次正常，停3秒，再发一次`RUN!`，等自动停。
6. 再发`RUN!`，约1秒后发送`STOP!`，确认两轮都停；再停3秒，发`RUN!`，约1秒后拨使能OFF，确认两轮都停。
7. 导出JSON发给我，并说明两轮方向、有无明显抖动、自动停/STOP/OFF是否均正常。

如果任何轮方向错误、明显反复启停或停车异常，STOP并拨OFF，结束本轮。软件无响应时使用电池主电源开关。不要用手阻挡轮子，也不要把车放到地上发送RUN。

3秒末尾未达到60不一定是故障，积分需要时间。本轮先验证双轮同时运行与停车，再根据日志判断是否延长观察。两轮达到相同架空轮速不能证明落地直行；轮径、负载和打滑仍会影响行驶。

## 读日志

示例字段形状（数字只是说明格式，不是实测）：

```text
DPI T=60 L=55 R=54 UL=600 UR=580 IL=420 IR=410 BAT=1340 DT=10000 ST=RUN F=-
```

| 字段 | 含义 |
|---|---|
| T | 两轮共同目标，单位mm/s；停车时0 |
| L / R | 左/右轮实测速度，前进均应为正，单位mm/s |
| UL / UR | 左/右轮向前驱动量的正数；实际A=UR、B=-UL |
| IL / IR | 左/右积分项对PWM命令的贡献，不是Ki参数 |
| BAT | 电池ADC原始值；1200仅是本轮台架门槛，不是电池截止标准 |
| DT | 最近读取间隔，单位微秒，通常约10000 |
| ST | RUN、DONE、STOP、OFF或故障状态 |
| F | 轮子故障归属L/R；共用停车条件或无故障显示- |
| RXE / TXD | 串口优化版累计接收错误数/因发送队列满而丢弃的遥测条数，正常应0 |

每200ms打印最近一拍数据，不能用它排除全部10ms采样中的波动。停车检查UL/UR/IL/IR都回0、L/R随后回0，并观察实物。
